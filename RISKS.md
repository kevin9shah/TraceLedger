# RISKS

Live risk register. Update on any new issue. Sponsor-tool problems are recorded here, never silently worked around.

## Sponsor-tool risks

| ID | Risk | Status | Mitigation / note |
|---|---|---|---|
| S1 | **TigerGraph** Savanna has *free credits, not free instances*. Smallest workspace TG-00 = **$1/hour while running**; credits valid 1 year | OPEN — brief's assumption was wrong | Verified against TigerGraph docs/FAQ 2026-10-29 (DECISIONS.md D9). **No payment method will ever be added** — their FAQ says expiry stops/terminates the instance "unless a payment method is added", so the worst case is a stopped workspace, never a charge. Operating rule: start only while building/demoing, stop immediately after. Smallest size. Schema + GSQL exported to `graph/export/`. Health-check via `scripts/tg_smoke.py` before demo. |
| S7 | Cloud Classic free-tier cluster (the brief's assumed "free tier, auto-stops after ~1h") **no longer exists** | CLOSED 2026-10-29 | Free tier removed Nov 2024; Classic closed to new users; AWS EOL 30 Sep 2026 (already passed). Do not follow any guide that references it |
| S8 | Community Edition (the free-forever option) is **unsupported on this machine** | CLOSED 2026-10-29 | Docker became available, so CE was re-examined and rejected on hardware grounds, not preference: TigerGraph's Docker guide states *"TigerGraph on Docker is not supported for ARM processors, including M1 Macs."* This host is `arm64` with **8 GB RAM** (their stated minimum; 24 GB recommended). Forcing `--platform linux/amd64` means emulating an unsupported config on minimum RAM — unacceptable for something the demo depends on |
| S12 | The Savanna console exposes a **workgroup** UUID (`tgcloud.io/groups/<uuid>`, dashed) that is easily mistaken for the **workspace** id (32-char hex, no dashes) the endpoint is built from | OPEN — a setup trap, not a code defect | `normalise_tg_host()` accepts a bare 32-hex workspace id and expands it to `https://<id>.i.tgcloud.io`; a dashed UUID deliberately does **not** match, so it is treated as a hostname and fails visibly rather than silently building a wrong endpoint. Documented in `docs/setup_sponsors.md` step 8 |
| S13 | `load_dotenv()` does not override variables already in `os.environ` | CLOSED 2026-10-29 | Caused a test to pass alone and fail in the suite. `tests/test_config.py` now clears every managed key in an autouse fixture. Also a real-world trap: a stale exported `TG_HOST` would silently beat `.env` |
| S11 | TigerGraph's own older docs show a **bare** Savanna hostname, but pyTigerGraph >=2.0 raises `Invalid URL scheme` on it | CLOSED 2026-10-29 | Confirmed by test `test_bare_host_would_have_failed_without_normalisation`. `config.normalise_tg_host()` accepts either spelling and adds `https://` for Savanna, `http://` for localhost. 10 parametrised cases + a test that the normalised value constructs a real `TigerGraphConnection` |
| S10 | Auto-resume could silently restart a suspended workspace and resume billing | **CLOSED 2026-10-29 — measured, not assumed** | Tested directly against a stopped workspace: every endpoint returns HTTP 500 with `"Auto start is not enabled for this workspace"`. Auto-start is **off**, so no script in this repo can wake the workspace or cause a charge. Stopping it in the console is therefore a hard cost stop. (The docs' auto-resume behaviour does not apply here.) |
| S9 | Savanna workspace stopped or out of credits at demo time | OPEN | SQL/SQLite root-cause path is built first-class, not a stub (needed for CP8 graph-vs-SQL regardless). Demo degrades to the SQL path **and says so**; cached graph output is never presented as live (G3, G10) |
| S6 | Savanna connects with a **database secret**, not username/password — the originally-written smoke test would have failed even against a healthy workspace | CLOSED 2026-10-29 | `scripts/tg_smoke.py` now uses `gsqlSecret` for Savanna and falls back to username/password only for self-hosted. Verified against pyTigerGraph 1.6 docs |
| S14 | The real Savanna workspace host format is `tg-<uuid>.tg-<number>.i.tgcloud.io`, **not** the `<32-hex-id>.i.tgcloud.io` that TigerGraph's docs and third-party guides describe | CLOSED 2026-10-29 | Cost significant setup time. Actual host verified working. `normalise_tg_host()` passes a full URL through unchanged, so both formats work. Secrets are created from the console's **Database Secrets** screen, not the GSQL shell — recorded in `docs/setup_sponsors.md` |
| S2 | **Cake Wallet** — which EVM chain supports *both* USDC and USDT must be confirmed in-app, not assumed | OPEN — blocking CP1 | Human to confirm in the app. Record result in PROGRESS.md and `data/real_txs.json`. |
| S3 | **Cake Wallet** testnet availability unknown | OPEN | If no testnet, use tiny mainnet amounts. Never request seed/keys (G2). |
| S15 | Wispr Flow inserts dictated text via **clipboard paste**, which any paste-blocking or input-sanitising handler in the review UI would silently break — while a keyboard-only test still passed | OPEN — binding constraint on CP9 | Measured 2026-10-29 (DECISIONS.md D13). CP9 must not call `preventDefault` on paste, must not rewrite field values on change, and must not clear fields on blur. Re-run `ui/dictation_test.html` against the real review form before ticking CP9 |
| S4 | **Wispr Flow** — sources conflict on whether a public API exists | OPEN | Treat as OS-level dictation only. UI must work with plain typing. Never fake an integration. No Wispr Flow code, SDK or API call exists in this repo. |
| S5 | `polygon-rpc.com` rejects keyless calls (`-32051 tenant disabled`) | CLOSED 2026-10-29 | Switched to `polygon-bor-rpc.publicnode.com`; `1rpc.io/matic` and `polygon.drpc.org` verified as fallbacks (DECISIONS.md D7) |

| S16 | **A live TigerGraph database secret was committed and pushed** in `.env.example` (commit `22573dd`, `origin/main`) | **ACTIVE — requires the human to rotate the secret** | The repo is **private** (GitHub returns 404 unauthenticated), so exposure is limited to the owner and any collaborators, not the public. Remediation: (1) delete the secret in Savanna's **Database Secrets** screen and create a new one — this is the only fix that matters, since removing a secret from git does not un-expose it; (2) put the new value in `.env` **only**; (3) `.env.example` scrubbed locally, commit pending; (4) history rewrite optional once the old secret is dead, and would need a force push (G13 — ask first). Prevented from recurring by `tests/test_no_secrets_committed.py` |

| S17 | **Live demo depends on venue network** — mainnet RPC reads and the Savanna workspace are both remote | OPEN — accepted (D17) | Rehearse on the venue network. Replay path from a stored tx hash, shown as **REPLAY** on screen and never presented as live (G3). Cache the verified token registry so the wrong-asset catch does not need a fresh RPC call |
| S18 | **Savanna workspace stopped at demo time** — it must be started manually and auto-start is off (S10) | OPEN — accepted | Start it before the session and confirm with `scripts/tg_smoke.py`. The graph beat is the only one that needs it; beats 1–3 run without TigerGraph. If it is down, say so rather than showing cached graph output (G10) |
| S19 | **A live transfer can fail or be slow** — wrong token picked in the wallet, insufficient gas, or slow inclusion in front of an audience | OPEN — accepted | Pre-fund the wallet with POL plus both tokens and rehearse the exact send. Poll by hash with a visible pending state. Keep the replay case ready. Never claim "final" or "guaranteed" — only "confirmed on-chain" at N confirmations (P10) |
| S20 | **The wrong-asset catch must be genuine** — a rule that fired on a magic string, or on the symbol, would make the demo theatre | **CLOSED 2026-10-29 — discharged by test** | The verdict derives from the transaction's Transfer events and `decimals()` read from the contract (D14). `test_catch_does_not_depend_on_the_symbol_string` is parametrised over `USDC`, `USDT`, `USDT0`, empty and `TOTALLY-WRONG` — the `CONFLICT` fires in all five. Demonstrated live: a token reporting `symbol='USDT0'` still **verifies** correctly when it is the invoiced contract |

## Product / method risks

| ID | Risk | Why it matters | Mitigation in build |
|---|---|---|---|
| P1 | Unproven demand | Customers may already be served | `docs/discovery.md` holds interview questions; pitch demand as hypothesis only |
| P2 | Incumbent overlap (Circle, Ripple Treasury, Tokenbooks, Reconciles) | "Isn't this just reconciliation?" | Target hard leftover cases; prove via benchmark. No "no one does AI reconciliation" claims |
| P3 | Infrequent use → weak subscription story | Pricing/GTM | Case-based tool first; monitoring + API noted in `BACKLOG.md` as validation paths |
| P4 | Synthetic-data overfitting | Demo works only on invented cases | Vary cases: split payments, legit repeated amounts, contradictory timestamps, partial payments, insufficient evidence. Mix real hashes with simulated business records |
| P5 | LLM hallucination | Confident wrong finding | G4/G5/G8 + validator layer + human review; track unsupported-claim rate |
| P6 | Bad source data (wrong network, stale RPC, parser bug) | Wrong conclusions | Verify chain ID; log RPC source per fact; unit-test parser on known txs |
| P7 | Graph as buzzword | "Why graph?" | Graph-vs-SQL benchmark on root-cause cases; report ties honestly |
| P8 | Fine-tuning claim unjustified | No data for it | Do not fine-tune; note as hypothesis in `BACKLOG.md` |
| P9 | Token confusion (USDC/USDT/lookalikes) | Wrong asset marked paid | G7: contract allow-list, decimals read from contract, lookalike test cases. **Confirmed live on Polygon 2026-10-29:** canonical Tether contract reports `symbol="USDT0"`, and two distinct live contracts both report `symbol="USDC"` (DECISIONS.md D6). Symbol is display-only in code |
| P13 | Cake Wallet may list the *bridged* USDC (`0x2791Bc…`) rather than native (`0x3c499c…`) | The sent token's contract must match the one the verifier expects, or a correct payment reads as wrong-asset | **Resolved by design change (D14):** token identity is read from the real transaction's `to` field and the `Transfer` event, never from a wallet UI label. Determined at CP2 from the actual transfer |
| P14 | A wallet's **receive address** is easily mistaken for a token contract — it was, in this project, for both tokens at once | Would have mis-verified every payment against an address holding no code | Caught by `scripts/verify_tokens.py`: `eth_getCode == 0x` fails verification with an explicit message. Any address entering the token allow-list must hold contract code and answer `decimals()` |
| P10 | Issuer freeze / blacklist | "Confirmed" ≠ "guaranteed" | Wording: "confirmed on-chain"; never "final"/"guaranteed" |
| P11 | Privacy of financial data | Invoices/ledgers are sensitive | Synthetic data only in repo; read-only; no real customer data |
| P16 | **TraceLedger scores 100% on a benchmark written by the same party that wrote the system.** Outcome accuracy 25/25, issue identification 17/17 | OPEN — the headline number must not be quoted externally | A benchmark the system passes perfectly has stopped discriminating. Cases were authored knowing which checks exist; the deterministic layer cannot fabricate an evidence ID (construction raises), so citation metrics are true by design; 25 cases cannot distinguish 100% from 92% (P12). **What is meaningful is the comparison of failure modes**, not the score. Stated prominently at the top of `BENCHMARK_RESULTS.md`. Needs adversarial cases from an independent author before any external claim |
| P15 | **CP4's realism review was not performed by anyone with web3/payments domain knowledge.** The human stated they do not know the domain and deferred to the model; the cases were therefore written and reviewed by the same party | OPEN — material limitation | Recorded rather than ticked as passed. The *chain* side is real and verifiable, so case realism is only at issue for the **business records** (invoice/ledger/approval shapes and the operator framing). Mitigation: cases are drawn from real transaction shapes, not invented ones; `C07` is explicitly flagged as the weakest business story. **Any claim about these cases must say "synthetic business records, realism not expert-reviewed"** (G10). Seek a review from an ops or treasury practitioner before any external claim |
| P12 | Small benchmark (25 cases) | Not production evidence | Label "preliminary, 25 synthetic cases" everywhere results appear |
